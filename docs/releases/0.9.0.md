# StratAgent 0.9.0 — Developer Preview

**Give your coding agent a workspace built for your project.**

Describe the work in your existing coding agent. StratAgent inspects the local
setup, helps explain what is needed, and lets you keep a sufficient environment
or review the smallest justified change. No additional LLM API key is required;
your coding host supplies the model and its usage limits still apply.

## What is new since 0.8.0

- A project-local first-party skill and `connect`, `start` and `next` guidance.
  The agent carries command arguments, model schemas, session IDs and review
  digests while you review meaningful choices. Existing progress is reused.
- A bounded, read-only inventory of local guidance, skills, roles and recorded
  StratAgent ownership. Existing user files stay under their current ownership.
- Grounded needs, coverage, reasons and alternatives before additions. A reviewed
  **keep** outcome needs no search and installs no environment files. Concrete
  gaps guide research when additions are justified.
- Exact operator-only acceptance bound to current project/environment state;
  stale context, drift, conflicts and interrupted transactions remain visible.
- Bounded proposal submission on stdin and additional read-only MCP guidance.
  Scoped model tools cannot approve installation or accept an assessment.
- A [natural-language quickstart](https://github.com/etrkk5/stratagent/blob/v0.9.0/docs/quickstart.md),
  with English and Turkish examples, plus controlled CLI acceptance for the
  no-addition path. This synthetic fixture does not represent a live model trial.

The existing reviewed research, portable outputs, ownership-aware lifecycle,
recovery, offline diagnostics and package verification remain available.

## Install and start

Python 3.11+ is required. Follow the
[verify/install guide](https://github.com/etrkk5/stratagent/blob/v0.9.0/docs/publishing.md#verify-and-install)
for the application wheel or native offline bundle. For a versioned source install,
follow the [quickstart](https://github.com/etrkk5/stratagent/blob/v0.9.0/docs/quickstart.md).
Then ask your coding agent to connect StratAgent to the intended project and review
its first-party skill changes. A host refresh/new session may be needed for discovery.

The six OS/Python ZIPs include the application, compatible PyYAML wheel, source,
SBOM, receipt and checksums. Direct wheel/source assets come from Ubuntu/Python
3.11 CI. `RELEASE-MANIFEST.json` records the exact source commit and successful
six-job main CI; `SHA256SUMS` covers eight payload assets and the manifest.
Verify signed GitHub workflow provenance too. Inner receipts retain `signed: false`;
external workflow attestations provide publisher/source evidence separately.

PyPI is deferred. A GitHub preview does not make `pip install stratagent-cli`
available. For an existing installation, use a separate Python environment for the
new package and retain project state. See the
[upgrade and rollback procedure](https://github.com/etrkk5/stratagent/blob/v0.9.0/docs/releasing.md).
Package upgrades do not silently approve or migrate workspace changes.

## Preview boundaries and support

This is a developer preview, not a production/GA release. Claude Code, Codex,
Antigravity and generic output contracts are documented; OS CI does not certify
all native host/version behavior. Fresh Claude Code/Antigravity sessions, 30 human
reviews and independent installation trials were explicitly waived, not performed
or passed. Preference, task-quality gains and retention remain unmeasured.

Local metadata and model judgments are evidence for review, not proof of coverage,
trust or activation. StratAgent does not autonomously launch agents, activate MCP
servers or execute arbitrary third-party code. Source scans and attestations do
not guarantee safety. The distribution SBOM excludes native-library/OS and vendored
build-tool closure; network filesystems and physical power loss remain outside
transaction assurance.

Use [support](https://github.com/etrkk5/stratagent/blob/v0.9.0/SUPPORT.md) for
non-sensitive reports and [private reporting](https://github.com/etrkk5/stratagent/security/advisories/new)
for vulnerabilities. Share a minimal synthetic reproduction, not private project
files, prompts, credentials or transaction backups. See
[readiness](https://github.com/etrkk5/stratagent/blob/v0.9.0/docs/release-readiness.md)
for the complete evidence limits.
